# DeDge DeepSeek Harness 0.1.95

修复“只有附件、没有正文”发送后的假等待状态，覆盖原生图片、长文本转文件和文件片段。官方 Harness 运行时保持 `0.2.0-rc.2`。

- 发送使用统一请求 ID，Harness 持久用户消息的 `source.rpcId` 是已送达的依据，不依赖非空文字。
- 已送达的用户输入替换临时卡片，不重复显示；真正等待模型的状态独立保留，后续输出或停止会清除。
- 旧运行时通过正文、附件、新消息 ID 与序号进行保守匹配；后台计划与加载出来的重复旧历史不能冒充发送回执。
- 晚到的回执不会把已完成消息变回 Waiting；所有权恢复重试复用请求 ID。

## 验证与边界

193 项 Vitest、类型检查、构建；合成 Webview 中测试仅图片、仅长文本附件、文件片段的受理、持久化、推理、完成及迟到回执顺序。runtime smoke 以本机模拟模型和临时工作区验证不带正文的原生图片及其请求 ID，不使用用户密钥或私人会话。

Windows 工作区根目录可写而某个旧子目录在受限令牌下不可写时，不能直接推断账号权限已损坏，应对比该子目录的能力 ACE 与完整性标签。本版没有引入自动、递归权限重置或全开放回退；本机事故的诊断/恢复记录不进入 VSIX 和仓库。

升级后需要由用户重新加载扩展界面才能使用新的发送状态逻辑；本包不会自动安装或重启 VS Code。
